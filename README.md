# Isogram: AI Text Detection

Isogram is a PyTorch project for detecting whether an English essay is
human-written or generated by a large language model. It trains on sampled,
source-tracked text datasets and serves predictions as
`{"prob_ai": float, "model_version": string}` from `POST /predict`.

## Setup

Use Python 3.11 or newer. The recommended setup path is `uv`, which installs
dependencies from `pyproject.toml` and the committed lockfile:

```bash
uv sync --extra dev --extra hf --extra kaggle
source .venv/bin/activate
```

If `uv` is not available, a regular editable pip install is still supported:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e ".[dev,hf,kaggle]"
```

Install local pre-commit hooks after setting up the environment:

```bash
uv run pre-commit install
```

## Data

The primary permissively licensed source is the Hugging Face dataset
`srikanthgali/ai-text-detection-pile-cleaned`, which declares an MIT license and
contains over 700k rows. The project does not need to train on the full source
pool; the dataset builder streams a deterministic, class-balanced sample and
writes train/validation/test CSVs.

Create a permissive-only dataset from the Hugging Face source:

```bash
python -m isogram.data.build_dataset --hf-sample-rows 60000
```

To merge that sampled Hugging Face source with the existing local DAIGT v2 CSV,
first confirm the local source license is acceptable for the intended use, then
run:

```bash
python -m isogram.data.build_dataset \
  --local-path data/raw/daigt-v2 \
  --local-source-name drcat-v2 \
  --local-license apache-2.0 \
  --hf-sample-rows 60000
```

The merged builder writes deterministic 80/10/10 stratified splits to
`data/processed/merged/train.csv`, `data/processed/merged/val.csv`, and
`data/processed/merged/test.csv`, plus `data/processed/merged/all.csv` and
`data/processed/merged/metadata.json`. The metadata records source rows, label
counts, deduplication counts, split sizes, seed, and the declared Hugging Face license.

The legacy DAIGT-only preparation path is still available for reproducing older
experiments: `thedrcat/daigt-v2-train-dataset`.

With Kaggle credentials configured:

```bash
python -m isogram.data.prepare --download
```

Or download the dataset manually from Kaggle, place the CSV under
`data/raw/daigt-v2/`, then run:

```bash
python -m isogram.data.prepare --raw-path data/raw/daigt-v2
```

Preparation writes deterministic 80/20 stratified splits to
`data/processed/train.csv` and `data/processed/val.csv`. Splits are seeded
(`--seed 42`) and saved to disk so the same split is reused across runs;
`data/` is gitignored.

## Training

Train the lightweight PyTorch baseline first:

```bash
isogram-train-hydra model=char_cnn
```

Then fine-tune DeBERTa with a custom PyTorch classification head:

```bash
isogram-train-hydra model=deberta
```

Both commands write checkpoints under `artifacts/checkpoints/` and metrics under
`reports/`. Hydra writes the resolved run config under `reports/run_configs/`,
and MLflow logs parameters, metrics, configs, dataset metadata, reports, and
checkpoints under `mlruns/`.

The direct argparse entrypoint is still available:

```bash
python -m isogram.train \
  --model char_cnn \
  --train data/processed/merged/train.csv \
  --val data/processed/merged/val.csv \
  --mlflow
```

## Evaluation

```bash
python -m isogram.evaluate \
  --checkpoint artifacts/checkpoints/deberta_best.pt \
  --data data/processed/merged/test.csv
```

The report includes ROC-AUC, PR-AUC, precision, recall, F1, Brier score, and the
selected threshold.

## Serving

```bash
python -m isogram.serve --checkpoint artifacts/checkpoints/deberta_best.pt
```

Open `http://127.0.0.1:8000` for the minimal UI, or call the API:

```bash
curl -X POST http://127.0.0.1:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"text":"This essay argues that careful source evaluation matters."}'
```

## Docker

```bash
ISOGRAM_CHECKPOINT=artifacts/checkpoints/deberta_best.pt docker compose up --build
```

## Latency Check

Run the service first, then:

```bash
python scripts/load_test.py --url http://127.0.0.1:8000/predict --requests 50
```

A Node.js version is also available:

```bash
node scripts/load_test.js --url http://127.0.0.1:8000/predict --requests 50
```

With Docker Compose:

```bash
ISOGRAM_CHECKPOINT=artifacts/checkpoints/deberta_best.pt \
  docker compose --profile loadtest up --build
```

Target: median latency under 5 seconds on CPU and under 1 second on GPU per essay.
